# 验证报告与原始证据

[strategy.md](strategy.md)保存项目测试策略。每个真实工作包使用独立目录，不创建虚构验收结果：

```text
validation/
└── <任务号>/
    ├── report.md                固定结论入口，保留所有已登记轮次
    └── runs/
        └── <轮次号>/
            ├── record.json      候选、环境、命令、退出状态、指标和边界
            └── <原始证据>       日志、JSON、资源数据、输入清单及哈希
```

报告至少说明候选身份、运行环境、实际命令、退出状态、关键指标、失败及中断轮次、适用边界和原始证据路径。同一工作包的证据不得散落在用户文档、公开文档或其他工作包中。

在项目根使用 `python .harness/tools/record_validation.py --help` 查看导入格式。工具只记录已执行的验证，不执行输入命令，不自动修改任务为通过。每轮使用新的 ID，记录一旦写入就不可覆盖；新增通过记录不能删除前面的失败和中断。

只有验收条件、当前实现哈希、实际测试、适用通过记录和报告一致，任务才可标记 verified 或 complete。登记的路径和 SHA-256 统一放入[追溯源](../traceability.json)；哈希检查提供一致性检测，不提供外部防篡改存储。Harness 自检不代替项目验收。
