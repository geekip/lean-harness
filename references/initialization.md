# 引导式初始化参考

## 跨平台运行

需要 Python 3.10+，初始化器与检查工具只使用标准库。所有命令通过 Python 解释器调用，无需 Bash、WSL、Shell 脚本或 `chmod`。选择 Git 初始化或配置远端时才要求已安装 Git；仅初始化本地资料可以不安装 Git。

下列单行示例使用当前工作目录的 `demo` 子目录，适用于 Windows、macOS 和 Linux：

```text
python "lean-harness/scripts/init_project.py" --target "demo" --project-type code --requirements-mode qa --git-mode skip
```

示例中的 `python` 可替换为本机的 `python3` 或 Windows 的 `py -3`。传入路径包含空格时保留双引号；原生 Windows 路径可以直接作为参数。生成的文本使用 UTF-8 和 LF，项目内链接使用 `/`；Python 子进程使用当前解释器及 UTF-8 管道。

## 必须明确的选择

只询问仍未知的选择，但不能根据仓库是否存在来推断是否初始化 Git。`.harness/` 和 `AGENTS.md` 默认可以通过 Git 同步，是否公开由用户自行决定，不设置专属的私有/同步模式。

| 选择 | 推荐默认值 | 影响 |
|---|---|---|
| 项目类型 | 必须询问，无默认值 | `code` 增加 `.editorconfig` 和面向用户的 `README.md`；两类项目都有 Harness 协作入口 |
| 创建 `.gitignore` | 不创建 | 仅代码工程询问；选择创建时传入 `--create-gitignore`，仅在文件缺失时生效；非代码工程不能使用该参数 |
| Git | 未要求时为 `skip` | `init` 只创建本地仓库；可配置远端，但不连接远端 |
| 需求处理 | `qa` | 启动引导式澄清；`existing` 记录已有来源；`defer` 暂时保持开放 |
| 来源处理 | 原地引用 | 只有用户明确选择时才复制到 `.harness/document/sources/` |

如果目标位于另一个 Git 仓库内部，未经明确要求不得创建嵌套仓库。已有 `.gitignore` 始终保留原样；不写入 Harness 忽略规则、反忽略规则或管理区块。默认可同步表示模板不主动排除这些文件，不会覆盖已有或全局忽略规则，也不会清理以前用户工程中的 Harness 区块。初始化不会自动暂存、提交、推送、增删现有索引记录或修改仓库可见性。

## 需求澄清与冻结

即使已有需求文档，也应推荐进行问答：文档经常遗漏默认值、失败行为、排除项、优先级、兼容性、迁移、安全、数据所有权和可量化验收标准。

按小而连贯的主题分轮提问。每个重要决定记录：

```text
Q-001 <决定标题>
问题：<用户可以直接回答的一个决定>
答复：<用户原始答复，不自行扩写>
待确认结论：<可测试的行为和边界>
开放事项：<仍存在的歧义，如无则写无>
来源：<文档路径或用户确认>
```

问答历史写入 `.harness/document/requirements-freeze.md`。向用户汇总需求范围、排除项、验收标准和未解决问题，请其明确确认；确认后才将相应结论标为冻结，并写入 `.harness/document/requirements.md`。未确认部分继续保持开放。推荐位置：

- 原始输入或导入副本：`.harness/document/sources/`；
- 评审后的需求基线：`.harness/document/requirements.md`；
- 用户对目标、范围和取舍的决定：`.harness/document/decisions.md`。

不能为了让目录完整而复制来源。除非用户选择导入，否则保留其权威位置，并在需求记录中明确来源。原始外部文件不是已冻结需求；机器追溯中的需求 `source` 指向 `document/` 内的评审记录。公开文档目录只放普通用户手册、操作指南和核心技术介绍；不要为存放需求讨论、计划或测试过程创建 `docs/`。这些目录不提供保密保护，敏感资料的导入、同步和公开由用户自行决定。

## 生成目录树

实际目录树随项目类型变化，交付时展示真实创建和保留的路径：

```text
project/
├── AGENTS.md                         协作入口和阅读顺序
├── .gitignore                        仅代码工程选择创建时生成；已有文件保留
├── .editorconfig                     仅代码工程；中立文本格式默认值
├── README.md                         仅代码工程；面向产品用户
└── .harness/
    ├── README.md                     协作资料入口和阅读顺序
    ├── project.json                  项目概况、布局版本和边界配置
    ├── traceability.json             唯一机器追溯与状态事实源
    ├── document/                     用户需求、决策、讨论与原始材料
    ├── design/                       技术架构、格式规范、接口契约
    ├── plans/                        已冻结的实施与验收方案
    ├── validation/                   策略及各工作包报告与原始证据
    ├── history/                      明确非当前事实源的历史快照
    ├── memory/                       跨任务有用的项目事实
    ├── progress/                     当前状态投影与不可覆盖的交接
    │   ├── dashboard.md              一到两屏的人类看板，自动生成
    │   ├── current.md                生成状态块与人工维护的详细恢复信息
    │   ├── tasks.md                  完整任务状态投影
    │   ├── deliverables.md           交付映射投影
    │   └── handoffs/                 只追加，不覆盖已有交接
    ├── skills/                       项目内按需使用的技能
    └── tools/                        Python 资料与追溯检查
```

上图包含可选文件，交付时应根据实际创建和保留的文件展示目录树，并标明已有文件未被替换。非代码工程不创建 `.gitignore`，但可能保留此前已有的文件。`AGENTS.md` 和 `.harness/` 默认可同步，不代表初始化器已将它们加入 Git，也不保证用户原有的忽略规则允许跟踪；是否公开由用户自行决定。

`progress/dashboard.md` 由追溯数据和项目概况生成，最多 50 行、4000 字符。项目真实创建时间未知时用 `project.created_at=null`，不把初始化日期当作创建日期；概述待澄清、不编造版本。没有确认范围或任务总量时不计算完成率。初始任务、设计、方案、能力、测试和验证记录均为空，只登记初始化交接，不用占位任务虚构项目进度。

根 `README.md` 包含产品定位、真实能力、支持边界、快速开始、配置入口、公开接口和许可；未确认的信息如实标注。不要把 Harness 自检命令、开发计划或内部文档入口写进去。

## 安全重复运行

初始化器创建缺失文件、保留已有内容，并报告跳过路径。已有 `.gitignore` 始终不改写；验证记录、历史快照和交接不可被覆盖选项改写。旧布局应先按[迁移说明](migration.md)迁移和审查，不自动生成第二套追溯源。模板替换需用户明确授权，并在替换后检查差异。
